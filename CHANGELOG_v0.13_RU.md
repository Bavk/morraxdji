# Universal Stream Control v0.13 — исправления целостности доступа

Дата: 22 октября 2026 г. Статус: исходный прототип; НЕ подтверждена сборка EXE/APK и работа с реальным пультом.

## Исправлено

1. **Удаление комнат стало local-first и для VPN-режима.** В v0.12 обработчик Windows перед удалением комнаты последовательно обращался к VPS для отзыва каждого оператора. Ошибка HTTPS/DPAPI/ретранслятора прерывала запрос и могла оставить комнату доступной. Теперь первым выполняется `DELETE /api/admin/rooms/:id` на Windows. Он блокирует выдачу новых токенов и сохраняет отложенное удаление в LiveKit, как реализовано в v0.12. Только после этого выполняется удаление устаревших VPN-пиров; ошибки возвращаются как предупреждение, не отменяя локальное удаление.
2. **Отзыв одного ключа работает без доступа к VPN-настройкам.** В `vpn-manager.cjs` локальный отзыв выполняется до расшифровки настроек ретранслятора. Если DPAPI/HTTPS/VPS неисправны, локальный доступ закрывается, а peer остаётся отмеченным как ожидающий удаления.
3. **Автоматическая очистка оставшихся VPN-пиров** запускается в активном Windows-приложении раз в 60 секунд после запуска сервера. Список активных ключей читается с Windows API; удаляются только пиры отсутствующих или отозванных ключей. Неуспешные удаления остаются в локальном реестре и повторяются. Это не фоновая облачная задача: когда Windows-программа остановлена, проверка не выполняется.
4. **Ограничение запросов к VPS:** не более трёх параллельных команд удаления вместо N последовательных запросов, чтобы долгие тайм-ауты одного оператора не задерживали всех остальных. Каждое успешно обработанное удаление сохраняется на диске.
5. **Более корректные предупреждения:** отсутствие файла настроек VPN при сохранившихся старых пирах не считается успешным удалением. Windows сообщает о незавершённой очистке, а локальная комната всё равно закрывается.
6. **Проверка бинарных файлов в GitHub Actions:** после сборки CI дополнительно проверяет наличие PE/MZ-заголовка и разумного размера EXE, а для APK — имя пакета и корректность его Android-подписи с помощью Android SDK `aapt`/`apksigner`. Сценарии подготовлены, но фактический запуск GitHub Actions не подтверждён.

## Тесты

- `RUN_TESTS.sh`: 63 из 63 Node.js-тестов пройдены, аудит комплектации, синтаксис JS/Bash, валидность Android XML.
- `StreamProfileTest.kt`: 7 из 7 проверок пройдены через локальный компилятор Kotlin JVM.
- Android Gradle/SDK, Docker Desktop, Electron/Vite с пакетами npm и реальное соединение с пультом не запускались. Из-за отсутствия доступа к npm/Android SDK **EXE/APK не собраны**.

## Совместимость и ограничения

- Формат кодов `USCV1` не изменялся; база комнат и `vpn-peers.json` сохраняют прежний формат.
- Не удаляйте файлы `local-server`, `vpn-settings.json`, `vpn-peers.json` при обновлении: они нужны для привязки выданных ключей к VPN-пирам.
- Удаление комнаты сначала закрывает локальный доступ, но уже выданный токен LiveKit может работать до истечения срока. Сохранён механизм повторного принудительного закрытия комнат из v0.12. До аппаратных испытаний мгновенное прекращение видеосеансов не гарантируется.
- VPN-шлюз остаётся отдельным публичным VPS при невозможности прямого входящего подключения; видеосервер и просмотр размещаются на Windows.
