# Universal Stream Control v0.10 — отзыв доступа и автоматизация сборок

## Исправлена опасная ситуация при отказе LiveKit

До v0.10 отзыв ключа сразу записывался в локальную базу, но при временной недоступности LiveKit активный видеосеанс мог не отключиться. Теперь Windows API **каждые 30 секунд** проверяет подключённых участников комнат, имеющих отозванные ключи, и повторяет отключение соответствующих участников. Проверка выполняется после запуска сервера, периодически и по команде администратора.

- Новая кнопка **«Проверить отключения операторов»** в боковой панели Windows вызывает защищённый административный API `/api/admin/reconcile-revoked`.
- Проверка не разрывает сеансы действующих операторов и зрителей.
- Ошибка одной комнаты или участника не прерывает проверку остальных.
- Одновременные периодические проверки не накладываются друг на друга; при закрытии HTTP-сервера таймер останавливается.
- В случае сетевой ошибки в ручном ответе отображается количество ошибок. Требуется повторная проверка после восстановления LiveKit.

**Ограничение:** гарантировать немедленное отключение во время аварии сети/LiveKit нельзя. Механизм работает только при запущенном Windows API и после восстановления LiveKit. Он не заменяет отзыв WireGuard-пира на VPS и не может отменить уже выданный JWT до истечения срока его действия, если LiveKit недоступен.

## Исправлена конфигурация Windows-сборки

В Windows-приложении Vite не имел конфигурации для фактического расположения `renderer/index.html` и для загрузки ассетов через `file://`. Добавлены `windows/vite.config.mjs` (`root: renderer`, `base: ./`, `outDir: ../dist`) и обязательная проверка `scripts/verify-ui-build.mjs` после Vite. Сборка должна остановиться с ошибкой, если в выходном HTML абсолютные ссылки на JS/CSS или отсутствуют сами файлы.

## Автоматическая сборка

Добавлен `.github/workflows/build-and-test.yml` с тремя независимыми стадиями:

1. Ubuntu: Node.js 22, тесты сервера, Windows-логики и VPN, проверка структуры исходного проекта.
2. Windows Server 2022 runner: сборка **неподписанного** установщика Electron NSIS; загрузка в артефакты запуска.
3. Ubuntu: JDK 17, Android SDK 35, Gradle 8.9, сборка **отладочного** APK; загрузка в артефакты запуска.

На момент передачи исходников **сборки в GitHub Actions не запускались**. Они могут обнаружить проблемы в зависимостях/Gradle, которые невозможно проверить локальным тестированием. Секреты Windows, Android и VPS не нужны для сборки исходного прототипа. Полученные EXE и APK необходимо испытать на компьютере и пульте до внедрения.
