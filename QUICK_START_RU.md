# Краткий порядок запуска Universal Stream Control 0.11

## Первый раз: администратор

1. Подготовьте VPS с публичным IPv4 и доменом. Установите Node.js >=20. Скопируйте туда папку `relay/` и выполните `sudo bash install-relay-ubuntu.sh vpn.example.com`. Добавьте сгенерированную конфигурацию Caddy, проверьте HTTPS и откройте UDP 51820.
2. На Windows установите Docker Desktop, Node.js >=22 и официальный WireGuard. Из папки `windows/` выполните `npm install` и `npm run dev`.
3. В Windows-приложении в секции «VPN» введите 4 значения, показанные установщиком на VPS, и нажмите «Сохранить VPN». Затем нажмите кнопку «Включить VPN на Windows» и подтвердите запрос UAC (WireGuard для Windows должен быть установлен). Приложение создаст службу WireGuard для туннеля `usc-host`. Альтернатива: импортировать `usc-host.conf` вручную.
4. Нажмите **«Проверить готовность Windows»**, чтобы увидеть состояние Docker, VPN, HTTPS-связи с VPS и занятость портов. В PowerShell администратора выполните `windows/setup-firewall.ps1` (но обязательно проверьте отсутствие других открытых правил), затем запустите сервер в режиме «VPN».
5. Создайте комнату, добавьте оператора, **скопируйте единый код USCV1**. Передайте его только нужному оператору.

## Уже используете VPS из v0.4?

В папке `relay/` есть `migrate-firewall-v0.4-to-v0.5.sh`. На VPS под root выполните его **в запланированное время**: он делает резервную копию `usc0.conf`, заменяет широкое правило переадресации на изоляцию пультов и перезапускает WireGuard (потоки кратковременно оборвутся). Проверяет, что обнаружена именно старая конфигурация v0.4; неизвестные настройки автоматически не трогает.

## На Android-пульте: оператор

1. Установите собранный APK.
2. Скопируйте на пульте код `USCV1....` и нажмите «Вставить код из буфера обмена» (или вставьте код в поле вручную).
3. Нажмите «Начать трансляцию» и разрешите системный VPN (при первом подключении).
4. Разрешите захват экрана Android и вернитесь в приложение пилотирования. Видео появится в соответствующей комнате на Windows. В панели ключей видны статусы «не в сети», «подключён», «транслирует».

Для следующих запусков код сохраняется зашифрованным: достаточно открыть APK, нажать «Начать трансляцию» и разрешить захват экрана.

**Ограничения:** Windows/VPS/Android и видеопередача пока НЕ проверены на реальных устройствах; проект требует сборки исходников и первоначальной настройки. При CG-NAT VPS необходим. Видеотрансляции работают только пока Windows-ПК запущен. Полные инструкции см. `README_RU.md`.

## Обновление с v0.5

Прежние коды `USCV1` работают без перевыдачи; не удаляйте каталог пользовательских данных Windows. Для расширенной диагностики замените `/opt/universal-stream-relay/relay.mjs` на VPS новым файлом и выполните `sudo systemctl restart universal-stream-relay`. Старый VPS без нового API продолжает обслуживать VPN, но диагностическая панель покажет предупреждение. Полные инструкции по резервному копированию см. `README_RU.md`.

**Проверено:** Node.js-тесты и статическая корректность конфигурационных файлов. **Не проверено:** установка VPN-службы на реальном Windows, сборка EXE/APK, экран Android-пульта и видео через интернет.

## Новое: настройка качества и просмотр на v0.7

На Android перед нажатием «Начать трансляцию» выберите профиль качества. Для нестабильного 4G используйте «Экономия»; по умолчанию выбран «Стандарт», а «Детали» требуют более надёжного канала. Профиль сохраняется и вступает в силу при следующем запуске передачи экрана.

В Windows в заголовке комнаты выберите «Авто», 2, 3 или 4 столбца. Нажмите «Крупно», чтобы выделить один поток, или дважды нажмите по изображению для полного экрана. Если окончательно оборвётся соединение просмотра с LiveKit, клиент предпримет повторные попытки. Не нужно перевыдавать операторские коды VPN.

## v0.8: проверить видео до подключения пульта

1. Запустите Windows-приложение, сервер LiveKit и создайте комнату.
2. Выберите её слева, затем нажмите **«🧪 Проверить видео»**.
3. В сетке должна появиться движущаяся картинка `USC | VIDEO SELF-TEST`. Программа подтвердит получение первого видеокадра.
4. Тест остановится автоматически через 30 секунд после успешного кадра, либо нажмите **«Остановить тест»**.
5. Если за 15 секунд кадра нет, сначала проверьте Docker, LiveKit и сетевые порты Windows. Только затем проверяйте Android и VPN.

Локальный self-test НЕ проверяет WireGuard, VPS или реальный экран Android. API авторизации операторов в VPN-режиме теперь принимает запросы только с выделенных VPN-адресов.

На Linux/macOS проверка исходников: `./RUN_TESTS.sh`; на Windows: `powershell -ExecutionPolicy Bypass -File RUN_TESTS.ps1`. Наличие 26 успешных тестов не означает успешную сборку EXE/APK.

## v0.9: исправление конфликтов Docker и отзыв доступа

1. Если после аварийного закрытия Windows-приложение пишет, что TCP 7880 или другие порты заняты, нажмите «Проверить готовность Windows». При обнаружении оставшегося контейнера появится кнопка **«Завершить оставшийся LiveKit и восстановить запуск»**. Подтвердите действие. Это остановит оставшиеся видеосеансы, но сохранит комнаты и ключи. Затем снова запустите сервер.
2. Если в режиме VPN при попытке отзыва ключа VPS недоступен, ключ на Windows может быть уже заблокирован, а VPN-пир остаётся зарегистрирован. Когда VPS восстановится, нажмите **«Проверить отзыв VPN-ключей»** в нижней части боковой панели.
3. Проверьте, что Docker Desktop действительно слушает порты LiveKit только на выбранном IP и 127.0.0.1, а не на всех интерфейсах. Пример PowerShell администратора: `Get-NetTCPConnection -LocalPort 7880,7881 -State Listen | Select-Object LocalAddress,LocalPort`. Для UDP: `Get-NetUDPEndpoint -LocalPort 7882`. Также проверьте реальные подключения с другой машины и политику Windows Firewall.
4. **Не ослабляйте конфигурацию до привязки `0.0.0.0`**, если новая схема не поддерживается конкретной версией Docker Desktop. Зафиксируйте ошибку и сначала проверьте поддержку host-IP port mapping.

Необходимость VPS при CG-NAT сохраняется. Нет гарантии работы на произвольном пульте: аппаратная прошивка может запрещать установку APK, VPN или захват экрана.

## Новое в v0.10 — повторное отключение отозванных операторов и сборочный CI

После отзыва ключа Windows каждые 30 секунд пытается отключить оставшийся активный LiveKit-сеанс, если прежняя команда не сработала из-за аварии. В боковой панели появилась команда **«Проверить отключения операторов»**. Команда «Проверить отзыв VPN-ключей» осталась отдельной: она удаляет WireGuard-пиров на VPS, когда тот снова доступен. Обе проверки важны.

Добавлен `.github/workflows/build-and-test.yml` для пробной сборки **неподписанного EXE** и **отладочного APK** в GitHub Actions; workflow ещё **не запускался**. Подробности в `BUILD_AND_TEST_RU.md` и `CHANGELOG_v0.10_RU.md`. Исходники прошли 41 Node.js тест и 7 автономных Kotlin-проверок; реальный VPN, Windows EXE, Android APK и экран пульта всё ещё **не проверены**.


**Исправление сборки v0.10:** Vite теперь использует `windows/vite.config.mjs` и проверку ссылок в `dist/index.html`. Проверьте результат `npm run build:ui` до упаковки EXE.

## v0.11: важное для существующих операторов

Перед обновлением сделайте резервную копию данных Windows `local-server`, в частности `vpn-peers.json`. С v0.11 чужой код `USCV1` не сработает через другой WireGuard-пир: видеосервер сверяет принадлежность ключа с VPN-IP оператора. При сохранении исходных файлов повторная выдача кодов не нужна. Если `vpn-peers.json` потерян, нельзя просто отключить новую проверку: восстановите резервную копию или создайте новое подключение.

Если при отзыве ключа VPS недоступен, Windows сообщает **«Ключ отозван на Windows, VPN-пир ещё есть на VPS»**. После восстановления соединения запустите «Проверить отзыв VPN-ключей».

Если возникла ошибка запуска, на первом экране нажмите «Проверить готовность Windows», затем «Сохранить диагностику без ключей». Внутри работающего сервера сохранение доступно из боковой панели. Диагностический JSON можно передать разработчику для анализа: токены, коды и имена операторов в него не входят.
