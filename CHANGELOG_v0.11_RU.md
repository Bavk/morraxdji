# Universal Stream Control v0.11 — привязка операторских ключей к VPN и безопасная диагностика

## Главное изменение: ключ работает только через VPN своего оператора

Раньше Windows проверял, что входящий адрес находится в диапазоне выданных WireGuard-адресов `10.77.0.100–10.77.0.240`. При этом правильный код оператора можно было использовать с **другого** активного VPN-пира.

Теперь сервер в режиме VPN дополнительно проверяет, что **IP источника** совпадает с адресом, выданным **тому же операторскому ключу**. Сопоставление происходит на Windows через `vpn-peers.json`; VPS не получает права выдавать видеотокены. Несовпадение, отсутствие записи и повреждённая конфигурация приводят к отказу, а не к ослаблению защиты. Режим `vpn-only` не запускается без функции проверки привязки. Это работает в дополнение к изоляции WireGuard на VPS и Windows Firewall, а не вместо них.

Если у оператора остался старый код `USCV1`, то **перевыдавать его не нужно**, при условии что сохранился соответствующий `vpn-peers.json`. Если файл потерян, авторизация в режиме VPN будет заблокирована: восстановите данные из резервной копии либо переоформите оператора штатным способом. Не отключайте проверку IP как обход проблемы.

## Корректная реакция на сбой VPN-ретранслятора при отзыве

Отзыв ключа сначала сохраняется локально, затем выполняется отключение WireGuard-пира на VPS. Если VPS недоступен, операция возвращает `{ok:true,vpnRemovalPending:true,warning:...}` вместо общей ошибки, ошибочно создававшей впечатление, что ключ не отозван. Администратор видит предупреждение и повторяет удаление на панели **«Проверить отзыв VPN-ключей»** после восстановления VPS. Удалённый ранее пир (HTTP 404) считается уже удалённым. При недоступном LiveKit отключение активного сеанса также повторяется механизмом v0.10.

## Обезличенный диагностический отчёт Windows

На стартовом экране и в панели работающего сервера появилась кнопка **«Сохранить диагностику»**. Она создаёт локальный JSON-файл с версией приложения, состоянием Docker, WireGuard, VPS и занятостью портов. Поля формируются из ограниченного перечня (allowlist): **исключены операторские коды, токены, приватные ключи, имена операторов, полные IP-адреса и пути к конфигурациям**. Это полезно, если потребуется разбирать сбой на реальном Windows-ПК. Автоматически файл никуда не отправляется.

## Испытания

- 45/45 Node.js unit/integration тестов, включая проверку соответствия VPN-адреса ключу, отсутствие проверки по умолчанию и обезличивание диагностического отчёта.
- 7/7 автономных Kotlin-проверок выбора профиля качества.
- Статическая проверка JavaScript, Android XML, Bash и структурная проверка упаковки.
- Реальные EXE и APK **не собирались**, Docker Desktop/WireGuard в настоящей сети и Android MediaProjection **не испытывались**.

Обновление v0.10 → v0.11: остановите активные сеансы, сделайте резервные копии каталога `local-server` на Windows и настроек VPS, установите/запустите новые исходники. При сохранении `vpn-peers.json` VPN-ключи и коды `USCV1` остаются прежними. Изменять `relay.mjs` на VPS для обновления с v0.10 не требуется.
