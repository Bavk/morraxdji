# Реальная проверка DJI RC Plus 2 — 22 октября 2026

Проверена сквозная LAN-передача с физического DJI RC Plus 2 (Android API 30) на установленный Windows v0.47. ADB использовался для установки и управления интерфейсом; adb reverse отсутствует, медиаданные шли через локальную сеть.

Создана отдельная тестовая комната и отдельный операторский ключ через локальный API работающего Windows-сервера. В Android введены локальный адрес и ключ; подтверждён системный запрос захвата экрана. Коды, серверные секреты и VPN-профили в этот отчёт не включены.

Первый запуск Android v0.29 выявил падение android.app.RemoteServiceException: Bad notification for startForeground. В LiveKit 2.29.0 стандартное уведомление ScreenCaptureService создаётся без smallIcon. Исправление задаёт собственное уведомление с каналом, маленькой векторной иконкой, текстом и ссылкой на приложение через ScreenCaptureParams. Источник SDK: https://github.com/livekit/client-sdk-android/blob/v2.29.0/livekit-android-sdk/src/main/java/io/livekit/android/room/track/screencapture/ScreenCaptureService.kt

Исправленный APK Android v0.30/versionCode30: [артефакт](https://github.com/Bavk/morraxdji/actions/runs/39813607319/artifacts/12441760612). SHA256 b2559886d3642c910b68c66efade4ee9364e096ae8db00493df1d1141dbe5cb5, совпал с SHA256SUMS.txt. [GitHub Actions](https://github.com/Bavk/morraxdji/actions/runs/39813607319) завершился успешно; прошли 203 Node-теста и Android unit/build.

Обновление через adb install -r было отклонено из-за разных debug-подписей CI. После явного согласия пользователя старое приложение удалено и установлена v0.30; настройки тестового подключения введены заново. Комнаты и ключи Windows сохранены. Для будущих бесшовных обновлений необходим постоянный закрытый ключ подписи, хранимый вне публичного репозитория.

После исправления dumpsys media_projection подтвердил активный TYPE_SCREEN_CAPTURE, API presence — online=true/streaming=true. На Windows визуально подтверждено настоящее изображение рабочего стола пульта, затем его изменение при переключении экранов. Передача продолжалась вне приложения-передатчика. На движении интерфейса наблюдались 1920×1080, около 10 FPS; это наблюдение одного сеанса, а не гарантированная производительность или измерение задержки. Качество в повторном сеансе — профиль «Детали». На неподвижном экране FPS может падать до нуля.

В промежуточной повторной попытке изменённый текст ключа дал HTTP401; восстановление точного ключа позволило снова подключиться. Ещё одна попытка остановлена через интерфейс во время управления. Окончательный сеанс подтвердил активный захват и отображение видео. Подтверждена повторная публикация после остановки; устойчивость при сетевых разрывах отдельно не испытывалась.

Трансляция оставлена включённой по завершении проверки, тестовая комната и ключ оставлены для продолжения. Для остановки: Universal Stream Operator на пульте → «Остановить трансляцию».

Не проверено: интернет/WireGuard-ретранслятор, захват реального полётного видео DJI Pilot, несколько физических пультов, длительная нагрузка, запись/архив именно реального потока, энд-ту-энд задержка. Синтетические тесты этих функций не заменяют аппаратные испытания. Никаких реальных ключей, профилей или снимков пользовательского содержимого в репозиторий не добавлено.
