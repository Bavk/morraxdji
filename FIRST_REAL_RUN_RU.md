# Первый реальный запуск: сценарий испытаний v0.14

Этот проект пока не испытан сквозным образом: успешные Node.js-тесты и автономные Kotlin-проверки **не означают**, что установленный APK/EXE будет работать на любом пульте.

## Что собрать

1. Загрузить исходники в **приватный** репозиторий GitHub.
2. Запустить Actions → «Test and build prototypes» → «Run workflow».
3. Windows-job проверит сборку интерфейса Vite, **откроет его в настоящем Electron** (без Docker), затем создаст неподписанный Windows NSIS EXE и проверит наличие модулей API в `win-unpacked/resources/server`.
4. Android-job должен выполнить `:app:assembleDebug` и верификацию подписи APK. При ошибке сборки использовать логи соответствующего job; файл нельзя считать готовым.
5. Файлы сохраняются в артефактах Actions, а не появляются автоматически в репозитории. Для установщика потребуется доверенное распространение; неподписанный EXE и debug APK предназначены только для испытаний.

## Первый тест без VPS (LAN)

1. На Windows установить новый EXE со встроенным LiveKit и запустить приложение.
2. Выбрать локальный IPv4 и режим LAN, запустить сервер.
3. Создать комнату и нажать «Проверить видео». Должна появиться движущаяся тестовая картинка. **Это проверяет только сервер и Windows-просмотр.**
4. На Android тестовом устройстве установить **debug APK**. Для LAN без VPN в этом прототипе доступно отладочное поле адреса сервера; указать `http://<LAN-IP>:3100` и операторский ключ `STRM_...`, полученный в Windows.
5. Подключиться, подтвердить захват экрана. Перейти в интерфейс пульта, убедиться в отображении изображения на Windows.

## Первый тест через VPN (интернет)

1. Поднять собственный VPS-ретранслятор по `relay/README_RU.md`; не использовать публичные демонстрационные серверы. Нужны домен и HTTPS для API, UDP 51820 для WireGuard.
2. В Windows один раз указать адрес и публичный ключ VPS, включить WireGuard с подтверждением UAC.
3. Запустить Windows сервер в режиме VPN. Создать отдельный код `USCV1` для тестового оператора.
4. На Android отключить Wi-Fi (проверить передачу через 4G/5G), вставить **один код** в приложение, разрешить VPN и захват экрана.
5. Проверить, что пульт появился в нужной комнате, экран читаем, связь после краткого обрыва сети восстановилась.

## Чеклист результатов для первого испытания

| Проверка | Ожидаемый результат |
|---|---|
| Запуск EXE | Появляется стартовый экран, встроенный LiveKit обнаружен |
| Самотест LiveKit | Движущееся тестовое видео получено в Windows |
| Установка APK | APK запускается на выбранном Android-пульте |
| VPN | На Windows виден интерфейс 10.77.0.1; соединение с VPS есть |
| Подключение | В комнате появился операторский поток |
| Ориентация экрана | Весь экран и информационные полосы пульта видны без обрезания |
| Смена сети | Поток после обрыва восстанавливается либо показывает явную ошибку |
| Отзыв ключа | Старый оператор больше не может подключиться |

**Безопасность:** код `USCV1` включает приватный ключ WireGuard. Не пересылайте его в общий чат, не выкладывайте реальные файлы `vpn-settings.json`, `vpn-peers.json`, `usc-host.conf`, `internal-secrets.json`, `rooms.json`, не отправляйте закрытые ключи вместе с диагностикой. Не открывайте UDP/TCP медиапорты на публичном интерфейсе Windows в режиме VPN.

**Ограничения:** для пультов без Android или с заблокированной установкой APK нужен другой способ захвата (например, HDMI/USB). Android может скрывать защищённый контент от MediaProjection; гарантировать захват любого стороннего приложения нельзя. Работу внутри конкретной прошивки проверять отдельно.
