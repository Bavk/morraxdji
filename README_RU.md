# Universal Stream Control v0.11 — Windows сервер/просмотр + встроенный VPN на Android

**Состав:** Windows-приложение одновременно запускает LiveKit SFU, API, создаёт комнаты/операторов и показывает видео; Android APK передаёт только экран пульта. Для связи через разные сети в Android встроен WireGuard (отдельное VPN-приложение оператору НЕ требуется).

> **СТАТУС:** инженерный прототип исходных кодов. Автоматические Node.js-тесты пройдены; реальная передача видео, VPN на Windows, работа Docker Desktop, сборка Android APK/Windows EXE и нагрузка на десятках операторов **не проверялись**. Никаких готовых подписанных APK и EXE в архиве нет.


## Изменения v0.11 — индивидуальная VPN-привязка и диагностика

- В VPN-режиме каждый операторский код проверяется не только по принадлежности IP к VPN-подсети, но и по **конкретному адресу WireGuard-пира, который получал этот ключ**. Вход с другого подключённого пульта по чужому коду отклоняется. Без сохранённого файла `vpn-peers.json` вход не разрешается: сохраните его при обновлении. LAN-режим отладки не затрагивается.
- Отзыв ключа при ошибке VPS возвращает предупреждение, что VPN-пир ещё не удалён, при этом Windows **уже блокирует выдачу новых токенов**. После восстановления VPS используйте «Проверить отзыв VPN-ключей».
- Кнопка «Сохранить диагностику без ключей» создаёт локальный отчёт для поиска проблем с Docker, портами и VPN. Файл не содержит операторских имён, секретов, кодов подключения и IP-адресов.
- Проверки: 45 Node.js тестов и 7 автономных Kotlin-проверок. Это **не** сборка EXE/APK или доказательство работы на реальном пульте. Подробности: `CHANGELOG_v0.11_RU.md`.

## Новое в v0.9 — защита сетевых интерфейсов и безопасное восстановление

**Что реализовано в исходниках:**

1. **LiveKit больше не публикуется на все адреса Windows по умолчанию.** `compose.yaml` теперь привязывает TCP 7880/7881 и UDP 7882 к `127.0.0.1` (локальный просмотр) и к выбранному LAN- или VPN-IP (операторы). В режиме VPN выбран адрес `10.77.0.1`. Формат публикации соответствует Docker Compose, но **работу host-IP mapping на установленном Docker Desktop необходимо проверить**. Если Docker не поддерживает такие привязки, запуск может завершиться ошибкой: **не заменяйте их на `7880:7880`, это расширит доступность видеосервера**. Подробнее: https://docs.docker.com/reference/compose-file/services/#ports
2. **Восстановление после аварии.** Если Windows-приложение завершилось, а его Docker-контейнер продолжил работать, в стартовом окне через «Проверить готовность Windows» или после неудачного запуска появляется кнопка «Завершить оставшийся LiveKit и восстановить запуск». Она останавливает **только проверенный compose-проект USC**, без удаления базы комнат, операторских ключей или WireGuard. Операция прерывает текущие трансляции.
3. **Одна копия приложения.** Electron использует single-instance lock, чтобы исключить конкурирующие процессы управления одним локальным сервером.
4. **Безопаснее отзыв ключей.** Локальная блокировка операторского ключа сохраняется даже при сбое команды LiveKit `RemoveParticipant`. Windows покажет предупреждение, что видеосеанс мог остаться активным. Если VPS недоступен в момент отзыва, VPN-пир остаётся в локальной очереди; после восстановления связи администратор использует «Проверить отзыв VPN-ключей», чтобы повторить удаление ранее отозванных пирингов.
5. **Android: защита от позднего ответа MediaProjection.** Если оператор нажал «Остановить» во время системного запроса разрешения на захват экрана, запоздалый ответ не должен запустить отменённый сеанс.

**Важные границы:** API Windows на TCP 3100 в этой версии всё ещё привязан к `0.0.0.0` (административные методы разрешены только из loopback, а выдача операторских токенов в VPN-режиме ограничена VPN-адресами). Обязательно настройте Windows Firewall и проверьте другие входящие правила. Это не защищает ПК от всех возможных воздействий на API. Обновление не отменяет необходимость публичного VPN-шлюза при CG-NAT.

**Проверка текущего архива:** 35/35 Node.js тестов, проверка JS/Bash и Android XML. Попытка автономного запуска Kotlin CLI теста профилей упёрлась в тайм-аут, поэтому не отмечена как успешная. Gradle, Android SDK и Docker Desktop отсутствуют в тестовом окружении; EXE/APK, реальные VPN-подключения и видеокадры с Android **не собирались и не испытывались**. Полный отчёт: `TEST_RESULTS_v0.9.txt`.

Подробнее см. `CHANGELOG_v0.9_RU.md`.

## Новое в v0.8 — проверка собственного видеотракта Windows и защита VPN API

**Тест видео без пульта.** Сначала запустите Windows-сервер, затем создайте или выберите комнату и нажмите «🧪 Проверить видео». Приложение создаст движущуюся **искусственную** тестовую картинку 640×360/10 FPS, опубликует её в выбранную комнату через LiveKit и попробует получить настоящий видеокадр в окне просмотра. Кнопка превращается в «Остановить тест». После успешного первого кадра тест завершается самостоятельно через 30 секунд; если за 15 секунд кадра не появилось, программа покажет ошибку. Тест не читает камеру/микрофон или экран пользователя, не создаёт постоянный ключ/оператора.

**Это только локальный тест видео Windows → LiveKit → Windows.** Он не проверяет WireGuard на VPS и передачу экрана Android. Подтверждение реального сквозного пути пульт → VPN → Windows по-прежнему требует оборудования. Выполнение встроенного теста на настоящем Windows в текущей среде ещё не подтверждено.

**VPN-доступ.** В режиме VPN выдача операторских LiveKit-токенов по `/api/operator/session` ограничена источниками `10.77.0.100–10.77.0.240`, а запросы с обычной LAN сети получают HTTP 403. В отладочном режиме LAN прежнее поведение сохранено. **Это не заменяет** Windows Firewall: API и Docker LiveKit слушают сетевые порты, для которых необходимо ограничить входящий трафик правилами `setup-firewall.ps1` и проверить отсутствие общих разрешающих правил.

**Проверки:** 26/26 Node.js, 7 Kotlin-проверок профилей качества; Android XML и JS/Bash синтаксис. Полный отчёт: `TEST_RESULTS_v0.8.txt`. Запуск `npm install` в текущем окружении не состоялся из-за DNS `EAI_AGAIN`: сборка Electron EXE/Android APK и реальная видеопередача не выполнялись. На машине разработчика с интернетом собрать GUI можно командами `cd windows && npm install && npm run dev`.

Подробности: `CHANGELOG_v0.8_RU.md`. Формат операторского кода `USCV1` не меняется.

## Новое в v0.7 — устойчивость видео и обзор большого числа потоков

- **Android: три профиля качества передачи экрана**: Экономия (запрос 640×360, 15 FPS, битрейт до 0,4 Мбит/с), Стандарт (1280×720, 15 FPS, до 1,2 Мбит/с) и Детали (1920×1080, 15 FPS, до 2,5 Мбит/с). По умолчанию Стандарт. Настройка сохраняется и применяется **до начала захвата**, а не переключает активный MediaProjection. Это предельные настройки кодировщика, а не гарантия точного битрейта/качества на каждом устройстве. LiveKit/WebRTC и Android могут уменьшать качество из-за сети или аппаратных ограничений.
- **Windows: гибкая видеосетка** — автоматическая, 2, 3 или 4 столбца, запоминает выбор. Кнопка «Крупно» для нужного потока, двойной щелчок по видео — полноэкранный режим. При показе одного потока остальные скрываются для экономии ресурсов клиента; с включённым `adaptiveStream` LiveKit может сократить их получение (зависит от конфигурации и кодировщика).
- **Windows: восстановление просмотра** после окончательного обрыва соединения с LiveKit: автоматические повторные попытки через 1, 2, 4, 8, 15 секунд (максимум 15 секунд). Кратковременное WebRTC-переподключение по-прежнему выполняет сам SDK. При смене комнаты все старые повторные попытки отменяются, и устаревший ответ не открывает чужую комнату.
- **Android: понятнее сетевые ошибки** — запрос авторизации повторяется при временных сбоях с растущей паузой, но неверный или отозванный ключ (HTTP 4xx) не опрашивается многократно. Поздние ответы API/LiveKit после нажатия «Остановить» игнорируются.
- **Совместимость:** формат `USCV1` и комнаты/ключи предыдущей версии не менялись. VPS и WireGuard-конфигурацию с v0.6 обновлять не обязательно.

**Границы восстановления:** после *окончательного* разрыва на Android приложение прекращает MediaProjection-сеанс; Android может требовать нового согласия на захват. Бесшовное восстановление применяется к временным обрывам, пока LiveKit сохраняет сеанс. Защита от остановки фоновых процессов зависит от прошивки и требует практического тестирования.

## Новое в v0.6 по сравнению с v0.5

- **Windows: включение VPN одной кнопкой.** После первой настройки VPS нажмите «Включить VPN на Windows». Приложение вызывает официальный `wireguard.exe /installtunnelservice ...` с подтверждением UAC. Не нужно вручную импортировать `usc-host.conf`. Служба Windows автоматически запускается при загрузке ОС. **WireGuard для Windows должен быть установлен отдельно; это не встроенный драйвер и не обход прав администратора.**
- **Проверка занятых портов.** Перед запуском Docker проверяются TCP 3100/7880/7881 и UDP 7882. При конфликте приложение показывает номер порта и назначение вместо непонятной ошибки контейнера.
- **Более полная диагностика.** Проверяется наличие WireGuard, состояние VPN-интерфейса и доступность HTTPS API на VPS; новая версия API сообщает, зарегистрирован ли Windows-пир и сколько VPN-пиров заведено (НЕ число реально подключённых операторов). Диагностика не доказывает, что UDP/видеопоток проходит до Android.
- **Android: «Вставить код из буфера обмена».** Оператору не требуется вручную вводить длинную строку `USCV1...`. Добавлена явная регистрация LiveKit-службы захвата экрана с типом `mediaProjection`, важным для Android 10+ и Android 14+. Служба запускается SDK после согласия на MediaProjection; работу на OEM-прошивках ещё необходимо проверить.
- **Обратная совместимость.** Формат `USCV1` и локальные данные v0.5 сохранены. Установленный VPS v0.5 желательно обновить: скопируйте новый `relay.mjs` и выполните `sudo systemctl restart universal-stream-relay`. WireGuard-пиры и ключи при этом сохраняются. Если VPS ещё не обновлён, Windows покажет отдельное предупреждение о старом API, а не объявит шлюз недоступным.

### Порядок перехода с v0.5 на v0.6

1. Завершите активные трансляции и остановите прежнее приложение. Сохраните резервную копию пользовательских данных Windows (особенно каталога `local-server`) и файлов VPS `/etc/universal-stream-relay` и `/etc/wireguard/usc0.conf`.
2. Обновите исходники Windows/Android. Не удаляйте существующий каталог данных Windows — он содержит комнаты, ключи и VPN-подключения.
3. Для нового диагностического API обновите `relay/relay.mjs` на VPS в `/opt/universal-stream-relay/relay.mjs`, затем перезапустите `universal-stream-relay.service`. Менять конфигурацию WireGuard и повторно выдавать коды операторам не нужно.
4. Если VPN-туннель `usc-host` уже включён, повторно нажимать кнопку активации не требуется. Запустите сервер и проверьте доступность текущих операторов.

## Что улучшено в v0.5 по сравнению с v0.4

- **Реальные статусы операторов в Windows:** «○ Не в сети», «● Подключён», «● Транслирует». Обновление каждые 8 секунд через защищённый административный API, который опрашивает локальный LiveKit RoomService.
- **Отзыв ключа отключает активного участника** через локальный LiveKit `RemoveParticipant`, а удаление комнаты завершает её WebRTC-соединения через `DeleteRoom`. Короткие операторские JWT теперь действуют **5 минут при установлении подключения**, ограничивая повторный вход с выданным ранее токеном в самохостируемом LiveKit. В VPN-режиме также удаляется WireGuard-пир. Указанные меры предназначены для контроля доступа; абсолютная моментальность при сетевых сбоях не гарантируется.
- **Защита на VPN-ретрансляторе:** для **новых** установок VPS разрешаются от Android к Windows только TCP 3100/7880/7881 и UDP 7882, плюс обратные установленные соединения. Прямое общение операторов друг с другом и доступ к произвольным сервисам Windows через VPN блокируется на ретрансляторе.
- **Диагностика Windows:** кнопка «Проверить готовность Windows» проверяет Docker Desktop, адреса и наличие/активацию VPN.
- **Android:** отображение восстановления LiveKit-соединения, остановка VPN после остановки Android-захвата экрана, сохранение кода после успешного соединения. Экранный захват всё ещё зависит от OEM/MediaProjection, не проверен на устройствах.

### Миграция действующего VPS v0.4

ВНИМАНИЕ: запуск нового установщика на уже существующем VPS **не меняет автоматически правила** в `/etc/wireguard/usc0.conf` (чтобы не ломать пользовательскую конфигурацию). ### Непроверенные участки

В этой среде выполнены Node.js тесты, статические проверки JS/XML/Bash. **Windows EXE и Android APK не собраны**, поскольку нет полноценного окружения Windows/Docker Desktop и Android SDK/Gradle; поэтому фактическое поведение WireGuard, MediaProjection и LiveKit на реальном оборудовании пока не подтверждено.

## Самое важное: без публичного адреса Windows нужен VPN-ретранслятор

Если ПК находится за CG-NAT провайдера, обеспечить прямое входящее соединение с мобильного интернета нельзя простым пробросом портов. Поэтому **режим VPN этой версии использует небольшой публичный Linux VPS**, который маршрутизирует WireGuard-пакеты между операторами и Windows. VPS **НЕ запускает LiveKit, не хранит комнаты и видео, не участвует в декодировании потоков**: видеосервер и экран просмотра остаются на Windows. На VPS в любом случае завершается WireGuard-шифрование; ретранслятор является доверенным сетевым узлом и может технически видеть внутренний незашифрованный HTTP-сигналинг. Используйте только свой сервер и оберегайте токен администрирования; для более строгой модели угроз потребуются дополнительный TLS до Windows и аудит.

```text
   Android-пульт A (4G)      Android-пульт B (Wi-Fi)    ...
    10.77.0.100                  10.77.0.101
         |                           |
         +------ WireGuard UDP ------+
                     |
         ПУБЛИЧНЫЙ VPS: UDP 51820 (10.77.0.254)
         VPN-маршрутизатор; HTTPS API учёта пирингов
                     |
                 WireGuard
                     |
                 WINDOWS ПК
               VPN 10.77.0.1
          API Node.js :3100 + LiveKit :7880/7881/7882
          Комнаты + ключи + просмотр на этом ПК
```

### Подключение оператора: один раз

1. Установить APK Universal Stream Operator на поддерживаемый Android-пульт.
2. Один раз **вставить единый код `USCV1....`**, созданный Windows. В нём уже находятся отдельный VPN-ключ оператора, адрес ретранслятора и секрет входа в комнату. Не требуется вводить IP и параметры сервера.
3. Нажать **«Начать трансляцию»**. Android при первом подключении покажет системное окно разрешения VPN. Затем покажет разрешение на захват экрана (может показывать каждый новый сеанс).
4. Вернуться в программу управления пультом; трансляция появляется в назначенной комнате Windows. При следующих запусках сохранённый код извлекается из Android Keystore: остаётся нажать кнопку и разрешить захват экрана.
5. VPN настроен как **split tunnel только на 10.77.0.1/32**. Остальной интернет, включая приложение управления пультом, в обычных условиях идёт напрямую, но некоторые специальные прошивки и одновременные VPN могут конфликтовать.

### Подготовка VPS (один раз для всей системы)

Требуются публичный Linux VPS (Ubuntu/Debian), собственный домен с A-записью, Node.js >=20, права root, WireGuard, Caddy. Сначала убедитесь, что домен направлен на публичный IP VPS. Скопируйте папку `relay/` на VPS. Из этой папки:

```bash
sudo bash install-relay-ubuntu.sh vpn.example.com
```

Скрипт установит WireGuard и Caddy, создаст интерфейс `usc0`, systemd-сервис для API добавления пирингов и выведет **четыре поля**: `HTTPS API`, `UDP endpoint`, `public key` и `admin token`. Скрипт **не перезаписывает** существующий `/etc/caddy/Caddyfile`: вручную добавьте содержимое `/etc/universal-stream-relay/caddy-snippet.txt` в вашу конфигурацию Caddy, проверьте `caddy validate` и перезагрузите Caddy. На VPS и в облачном фаерволе откройте TCP 80/443 и UDP 51820. API управления слушает **только 127.0.0.1:8777**; наружу его выпускает только Caddy по HTTPS, под длинным токеном.

**Секрет `admin token` нельзя передавать операторам, помещать в APK или копировать в общие чаты.** Он даёт право добавлять VPN-устройства на VPS. VPS должен быть защищён, регулярно обновляться, иметь контроль доступа и резервные копии.

### Подготовка Windows (один раз)

1. Установите Docker Desktop (Linux containers, WSL2), Node.js >=22 и [официальный WireGuard для Windows](https://www.wireguard.com/install/). WireGuard Windows — **однократная системная зависимость администратора**; отдельное приложение для Android-операторов не требуется.
2. Откройте Windows-проект и запустите:

```powershell
cd windows
npm install
npm run dev
```

3. В Windows-приложении откройте **«VPN / подключение через интернет»**, впишите четыре поля, выданные установщиком VPS, и нажмите «Сохранить VPN».
4. Будет автоматически зарегистрирован VPN-пир Windows на VPS, а в `%APPDATA%\\universal-stream-control-windows\\local-server\\usc-host.conf` (точный путь показан в интерфейсе) появится локальная конфигурация Windows.
5. Нажмите **«Включить VPN на Windows»**, подтвердите UAC. Приложение использует официальный `wireguard.exe` и устанавливает туннель как службу `WireGuardTunnel$usc-host`; вручную импортировать файл больше не обязательно. На ПК должен появиться IPv4 `10.77.0.1`. Если кнопка недоступна, можно по-прежнему вручную импортировать `usc-host.conf` в WireGuard и активировать туннель.
6. В Windows-приложении выберите **VPN — интернет через ретранслятор** и нажмите **«Запустить сервер и просмотр»**. Docker запускается локально; LiveKit объявляет виртуальный адрес `10.77.0.1`.
7. Создавайте комнаты и ключи. При создании каждого ключа Windows автоматически регистрирует отдельный VPN-пир на VPS и показывает **единственный код `USCV1....`**. При отзыве кода Windows пытается отозвать и VPN-пир. Если VPS недоступен, локальная блокировка выполняется, но удалённый пир нужно удалить после восстановления связи.

### Крайне важно про Windows Firewall

В режиме VPN ПК должен принимать входящий трафик с VPN-интерфейса на **TCP 3100, TCP 7880, TCP 7881, UDP 7882**. Не открывайте эти четыре порта из интернета и по незащищённому LAN. Ограничьте правилами брандмауэра до доверенной VPN-подсети/интерфейса; также ограничьте доступ пирингов к другим сервисам Windows (например, SMB и RDP). В архив добавлен `windows/setup-firewall.ps1`: запускайте его в PowerShell администратора для создания правил только на VPN-подсеть, но обязательно проверьте, что другие правила не открывают те же порты всем. Docker Desktop может публиковать сервисы на всех интерфейсах, поэтому проверка правил брандмауэра ОБЯЗАТЕЛЬНА. Публичным на VPS должен быть только WireGuard UDP 51820 и HTTPS 443/TCP (80/TCP для выдачи сертификатов).

### Сборка Android APK

Нужны Android Studio, Android SDK API 35, JDK17, Gradle (проект не включает Gradle wrapper). Папка `android/` — стандартный Gradle Android-проект. Для сборки из Android Studio запустите `assembleDebug` или `assembleRelease`; имеется вспомогательный `build-apk.ps1` для Windows. Зависимости: LiveKit SDK и `com.wireguard.android:tunnel:1.0.20260102`. На Android появится запрос `VpnService` при первой попытке и запрос MediaProjection перед началом экранного потока.

> Обратите внимание: на некоторых пультах невозможно устанавливать APK или запрещён системный захват экрана; некоторые производители урезают Android VpnService. Это не устраняется только изменениями серверного ПО. В Android одновременно разрешён лишь **один** активный VPN, поэтому встроенный WireGuard может конфликтовать с другим корпоративным VPN.

### Сборка установщика Windows

```powershell
cd windows
npm install
npm run dist:win
```

Установщик Electron не включает Docker Desktop или WireGuard for Windows. Для внедрения «всё в одном EXE» понадобится подписанный установщик Windows с установкой драйвера/служб по UAC и дистрибуцией лицензированных компонентов — это отдельный этап.

## Защита и ограничения прототипа

- У каждого оператора отдельный ключ доступа LiveKit и отдельная WireGuard-пара. Доступ к комнате выдаёт только API на Windows, а не VPS. Локальная база хранит **хеши** операторских токенов. VPN-токен для управления VPS сохраняется через Windows DPAPI; приватные ключи в `.conf` защищайте правами доступа/DPAPI вручную. На Android одноразовый код зашифрован AES-GCM ключом из Android Keystore.
- `USCV1....` — **секрет**, в нём приватный ключ конкретного пульта. Не публикуйте коды, не снимайте скриншоты общим доступом, при утечке немедленно отзывайте ключ.
- Для split tunnel Android подключается к `http://10.77.0.1:3100` и `ws://10.77.0.1:7880` **внутри защищённой VPN-сети**. При этом внутренняя HTTP/WSS-часть в прототипе не имеет второго слоя TLS. Владельцу VPS теоретически доступен сигналинг; не используйте чужой/недоверенный ретранслятор.
- WebRTC медиа использует DTLS-SRTP поверх туннеля. Видео не сохраняется по умолчанию. Звук, чат и управление дроном отсутствуют.
- Ранее действующий JWT LiveKit может сохранять права до пяти минут при новом входе. Удаление VPN-пира прекращает новые подключения, но не является гарантией мгновенного удаления всех активных WebRTC-сессий. Принудительное отключение через `RemoveParticipant` добавлено в v0.5, но при недоступности LiveKit может потребоваться повтор операции и проверка состояния.
- Для десятков пультов нужен достаточный исходящий интернет Windows и оплачиваемая передача данных VPS: суммарный трафик примерно складывается из битрейтов всех потоков; параметры нагрузки и качества нужно измерить.
- На Windows может активироваться неверный сетевой профиль, Docker NAT может некорректно объявлять ICE-кандидаты, а Android OEM может останавливать VPN или MediaProjection. Реальная проверка обязательна.
