# Universal Stream Control v0.8 — журнал изменений

Дата: 22 октября 2026 г.

## 1. Проверка видеотракта внутри Windows

- В панели комнаты добавлена кнопка **«🧪 Проверить видео»**.
- Windows Electron создаёт синтетическую анимированную картинку 640×360, 10 FPS через `HTMLCanvasElement.captureStream()`. Камера, микрофон и содержимое экрана не считываются.
- Приложение получает **временный токен публикации (90 секунд)** от локального admin API, создаёт отдельное LiveKit-подключение и публикует единственный `screen_share`-видеотрек.
- Приложение сопоставляет идентификатор тестового отправителя с полученным зрителем видео и фиксирует получение **видеокадра**, используя Chromium `requestVideoFrameCallback` (либо событие `playing`, если API недоступен).
- Если кадр не поступил в течение 15 секунд после запуска публикации, выводится ошибка. После успешной проверки тестовый поток автоматически останавливается через 30 секунд; также есть ручная остановка.
- При смене комнаты, остановке сервера и выходе из Windows-приложения тест завершает отправку, очищает таймеры и освобождает медиа.
- Новая комната или постоянный операторский ключ при тестировании **не создаются**.

**Граница проверки:** этот тест помогает проверить *локальный* путь Windows Publisher → LiveKit → Windows Viewer. Он **не проверяет** удалённый WireGuard, VPS, сетевые операторы или захват Android-пульта. В текущем окружении реальный видеоцикл внутри Electron тоже ещё не исполнялся: подготовлены реализация и модульные/HTTP-тесты.

## 2. Защита API в VPN-режиме

- В режиме VPN операторский API выдаёт токены только запросам с адресов выделяемого диапазона `10.77.0.100–10.77.0.240` (включая IPv4-mapped IPv6 представление).
- Попытка обратиться к `/api/operator/session` с LAN или loopback в этом режиме получает HTTP 403.
- Локальный административный API по-прежнему доступен Windows через loopback. Режим LAN для отладки остался без нового IP-фильтра.
- Это не подмена WireGuard-аутентификации и **не заменяет правила Windows Firewall**, особенно для портов LiveKit 7880/7881/7882.

## 3. Тестирование и поддержка сборки

- Добавлены модульные тесты тестового видеопотока, его таймеров, отмены, раннего появления кадра, проверки токенов и ограничения операторских IP.
- Добавлен `RUN_TESTS.sh` для Linux/macOS; `RUN_TESTS.ps1` включает новые тесты и больше не запускает повторно старые.
- **26 из 26 Node.js-тестов проходят.** Отдельно пройдены 7 проверок Kotlin-профилей качества, синтаксис JavaScript/Bash и парсинг Android XML.
- Запуск `npm install` для Windows-приложения в среде разработки завершился ошибкой `EAI_AGAIN` (DNS к `registry.npmjs.org` недоступен). Поэтому Vite/Electron не собраны, Windows EXE и Android APK не выпущены.
- Исходники несовместимых изменений в `USCV1` и базе комнат **не вносят**. Повторная выдача ключей не требуется.

## Что проверить на настоящем Windows-ПК

1. Установить Docker Desktop, Node.js 22+, зависимости в `windows/`, собрать UI и запустить Electron.
2. Запустить локальный сервер и создать комнату.
3. Выбрать комнату и нажать «🧪 Проверить видео». Убедиться, что движущаяся тестовая картинка появляется и Windows сообщает об успешном кадре.
4. Настроить реальный VPN-шлюз, включить WireGuard на Windows, проверить правила Firewall; подключить Android-пульт.
5. Проверить реальную задержку и стабильность в 4G/5G. Тест из п. 3 этого не доказывает.
