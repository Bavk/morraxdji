# Windows v0.19 — архив видеозаписей

Кнопка «Архив записей» доступна на стартовом экране и в боковой панели сервера. Для просмотра сохранённых видео запускать сервер или подключать пульты не требуется. Просмотр архива не останавливает текущие трансляции.

Новые успешно завершённые записи добавляются в архив автоматически. Каждая строка содержит имя пульта/комнаты, дату, размер и путь файла. Можно искать по названию, имени файла и дате; список разбит на страницы по 30 записей. Метаданные сохраняются между запусками программы в локальном recordings-index.json внутри профиля приложения.

- «Смотреть» открывает видео во встроенном проигрывателе с обычными органами управления. «Закрыть видео» освобождает файл; закрытие архива также останавливает воспроизведение.
- «В папке» показывает выбранный файл в проводнике.
- «Добавить WebM» позволяет добавить старые записи, в том числе сделанные v0.18. Файлы не копируются и не перемещаются. При повторном выборе того же пути дубликат строки не создаётся; сохранённые название и дата остаются прежними.
- «Убрать» удаляет только строку из списка после подтверждения. Сам видеофайл остаётся на диске и может быть добавлен снова.
- Для перенесённых или удалённых файлов показывается «Файл недоступен»; такая строка сохраняется до ручного удаления. «Обновить» повторно проверяет наличие файлов.

Дата новых записей берётся из начала сеанса записи, дата вручную добавленных файлов — из времени изменения файла. Метаданные хранятся локально, файлы остаются в выбранных пользователем папках. При сбое сохранения индекса запись видео не объявляется неудачной: программа сообщает, что сохранённый файл нужно добавить в архив вручную. Повреждённый индекс не перезаписывается автоматически.

Для воспроизведения используется отдельный локальный media-протокол, который открывает только известные архиву WebM-файлы по идентификаторам. Путь к произвольному файлу нельзя передать в ссылке воспроизведения. Передача поддерживает HTTP Range и не требует чтения целого видео в память основного процесса. Для повреждённого или перемещённого файла проигрыватель показывает ошибку.

## Проверки

97 Node-тестов, включая сохранение/восстановление индекса, параллельное добавление, отсутствие дубликатов, поиск, недоступные файлы, удаление только метаданных, сохранение повреждённого индекса, проверку формата, Range/HEAD и ограничение media-протокола известными идентификаторами.

В реальном Electron с нативным LiveKit проверяются автоматическое добавление двух новых записей, декодирование видео внутри архива через локальный media-протокол, поиск, команда показа в папке, удаление только строки и повторное добавление файла. Проверка показа в папке валидирует выбранный путь без открытия окна проводника на CI. Дополнительно проверен пустой архив на стартовом экране без работающего сервера. Прежние проверки записи, закрытия окна, видеостены и статистики сохранены.

Android APK v0.15 совместим, переустановка не требуется. Docker и WSL2 не нужны. Физические пульты, длительные записи и нагрузка на большом числе источников требуют испытаний на пользовательском оборудовании.
